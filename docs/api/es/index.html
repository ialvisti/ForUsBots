POST /forusbot/vault-file-upload Enviar archivo (binario) → 202 Accepted

Recibe el cuerpo binario (PDF, Excel o CSV) con metadatos en headers. Tipos de archivo soportados: .pdf, .xlsx, .xls, .csv. El servidor inicia sesión (TOTP), completa el formulario y procesa el job de forma asíncrona. Devuelve 202 con jobId y ETA.

Parámetros (Headers)

Nombre Ubicación Tipo Req Descripción
x-auth-token header string sí Debe coincidir con la variable SHARED_TOKEN.
x-filename header string sí Nombre de archivo. Debe terminar en .pdf, .xlsx, .xls, o .csv.
x-meta header string (JSON) sí Ver esquema.
Content-Type header enum sí application/octet-stream, application/pdf, application/vnd.openxmlformats-officedocument.spreadsheetml.sheet (.xlsx), application/vnd.ms-excel (.xls), o text/csv.

Request: x-meta (simplificado)

{
  "planId": 580,
  "formData": {
    "section": "CONTRACTS & AGREEMENTS",
    "caption": "Recordkeeper Agreement",
    "captionOtherText": "(requerido solo si caption = 'Other')",
    "status": "Audit Ready",
    "effectiveDate": "2025-05-02"
  },
  "options": {
    "confirmDelayMs": 5000,
    "fastExit": false,
    "snifferWindowMs": 7000,
    "evidenceOnSuccess": false
  }
}

POST /forusbot/sandbox/vault-file-upload Validar sin lanzar un job (dry-run)

Validador de prueba. No requiere auth. Valida x-filename y parsea/valida x-meta. Si se envía binario, solo se cuenta pero no se procesa. Devuelve 200 con eco normalizado o 4xx ante errores de validación.

Parámetros (Headers)

Nombre Ubicación Tipo Req Descripción
x-filename header string sí Debe terminar en .pdf, .xlsx, .xls, o .csv.
x-meta header string (JSON) sí Misma forma que x-meta del upload.
Content-Type header enum no application/octet-stream o application/pdf si se envía binario.

POST /forusbot/scrape-plan Extraer módulos de un plan (en cola)

Requiere auth (x-auth-token). Encola un job de scraping para un plan. Extrae datos estructurados de 6 módulos: basic_info (16 campos), plan_design (26 campos), onboarding (6 campos), communications (6 campos), extra_settings (10 campos), feature_flags (3 campos). También extrae el historial de notas del plan. Usa GET /forusbot/jobs/:id para consultar hasta completar.

Body

{
  "planId": "627",
  "return": "data|html|text|both",    // por defecto: "data"
  "strict": false,                     // fallar si hay error en módulo/campo
  "includeScreens": false,             // incluir capturas de evidencia
  "timeoutMs": 30000,
  "modules": [
    "basic_info",                      // extraer todos los campos
    { "key": "plan_design", "fields": ["record_keeper_id", "enrollment_type"] }
  ]
}

communications 6 Texto DAVE, logo, participantes en español, e-statement, sorteo
extra_settings 10 Modo de carga RK, año del plan, reglas de elegibilidad ER match
feature_flags 3 Payroll X-Ray, problema de nómina, carga simple

POST /forusbot/search-participants Buscar participantes (en cola)

Requiere auth (x-auth-token). Normaliza criterios y opciones, inicia sesión, ejecuta la búsqueda en el portal y encola el job.

Body

{
  "criteria": {
    "companyName": "Acme Inc.",
    "fullName": "Jane Doe",
    "email": "jane@acme.com",
    "ssn": "1234",                 // últimos 4 (o 9)
    "phone": "4155551234",         // 10 dígitos
    "participantId": "98765"
  },
  "options": {
    "fetchAllPages": true,
    "pageLimit": 3,
    "maxRows": 60,
    "timeoutMs": 12000,
    "evidenceOnSuccess": false
  }
}

Interacción: cuando fetchAllPages=true, el bot avanza por páginas hasta pageLimit. maxRows limita el total de filas devueltas. La respuesta inmediata es 202 Accepted con jobId; el resultado final del job incluye las filas y la paginación mostrada abajo.

POST /forusbot/update-plan Actualizar campos del plan (en cola)

Requiere auth (x-auth-token) y está restringido a direcciones de correo autorizadas. Actualiza campos de configuración del plan vía automatización con Playwright en el portal del empleador. Acepta cualquier atributo name del formulario de edición del plan. Devuelve 202 con seguimiento del job.

Body

{
  "planId": "627",
  "note": "Actualizando diseño del plan según revisión anual",
  "updates": {
    "company_name": "Nombre de Empresa Actualizado",
    "effective_date": "2025-06-01",
    "default_savings_rate": "3",
    "employer_contribution_formula": [
      { "match_value": 100, "percent_pay": 3 },
      { "match_value": 50, "percent_pay": 2 }
    ],
    "enrollment_type": "Elegible automático",
    "blackout_begins_date": "2025-12-20",
    "blackout_ends_date": "2026-01-15"
  },
  "includeScreens": false,
  "timeoutMs": 30000
}

Formato de nombres de campo: Usa el atributo name del formulario de edición del plan (snake_case). Aliases aceptados para el envelope de la solicitud: planId / planID / id, y note / description / noteDescription.

Campos Comúnmente Actualizados

Campos frecuentemente actualizados (referencia) 
company_name, official_plan_name, ein, effective_date, status, status_as_of,
record_keeper_id, rk_plan_id, external_name, enrollment_type, employer_contribution,
default_savings_rate, employer_contribution_formula, employer_contribution_cap,
employer_contribution_timing, first_deferral_date, blackout_begins_date,
blackout_ends_date, plan_year_start, rk_upload_mode, payroll_xray, payroll_issue,
alts_crypto, max_crypto_percent_balance, website_live_date

Casos Especiales

  • Campos de fecha (cualquier clave que termine en _date): Deben estar en formato YYYY-MM-DD o null.
  • employer_contribution_formula: Array de objetos de tier. Cada tier requiere: { "match_value": número, "percent_pay": número }
  • Campos desconocidos: Causarán un error de validación. Verifica los nombres de campos en el formulario de edición del plan.

POST /forusbot/email-trigger Disparar comunicaciones por email (en cola)

Requiere auth (x-auth-token). Dispara varios tipos de comunicaciones por email a participantes del plan. Soporta 10 tipos diferentes de email incluyendo estados de cuenta, onboarding, comunicaciones de patrocinador y emails genéricos. Siempre envía a todos los participantes.

Tipos de Email

  • statement_notice - Notificaciones de estados de cuenta trimestrales
  • sponsor_quarterly_email - Actualizaciones trimestrales del patrocinador
  • onboard_communications - Emails de onboarding
  • new_hire_communications - Emails para nuevos empleados
  • generic_email - Comunicaciones genéricas con audiencia personalizada
  • monthly_balance - Actualizaciones de saldo mensual
  • year_end_notice - Notificaciones de fin de año
  • notify_auto-escalation - Alertas de auto-escalación
  • summary_annual_notice - Avisos de resumen anual
  • force_out - Notificaciones de force out
