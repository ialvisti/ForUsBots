Descripción general

ForUsBots expone nueve bots de Playwright para cargas al vault, scraping de participantes y planes, búsqueda de participantes, reset de MFA, actualización de participantes y planes, disparo de emails y gestión de usuarios del portal. Las operaciones protegidas usan la cuenta del portal asociada al token, TOTP cuando aplica y el flujo asíncrono 202 + jobId.

Docs auditadas: 2026-07-16 · API v2.5.0

URLs base

  • DEV http://localhost:10000
  • Render https://forusbots.onrender.com

Todas las rutas de la API están bajo el namespace /forusbot.

Autenticación

Las rutas protegidas aceptan x-auth-token o Authorization: Bearer …. Los tokens se definen en el registro ignorado por Git tokens.json (o TOKENS_FILE). Un despliegue puede materializar ese archivo desde el secreto TOKENS_JSON. Un token ausente o desconocido devuelve 401. 

x-auth-token: TU_TOKEN

Los roles son admin, user, pa_lead, rm_lead, ops_lead e imp_lead. El scope efectivo combina los defaults del rol con deniedFeatures, deniedEndpoints y allowedEndpoints del token; un allow exacto prevalece. Consulta identidad, alias de cuenta y scope con GET /forusbot/whoami.

Locks, settings, métricas, versión y OpenAPI servido son solo admin. Update-plan y users-management además usan allowlists de email; el rol admin no evita esa restricción. Status depende de los flags runtime.

Vault File Upload Bot

Automatiza cargas seguras al portal de empleadores de ForUsAll. Acepta cuerpo binario y metadatos en headers; devuelve 202 Accepted con jobId para consultar.

Endpoint

POST /forusbot/vault-file-upload (auth)

Headers

Nombre Tipo Req Descripción
x-auth-token string sí Token compartido de API.
x-filename string sí Nombre original. Soporta .pdf, .xlsx, .xls, .csv y .zip.
x-meta JSON string sí Incluye planId y formData (section, caption, status, effectiveDate).
Content-Type enum sí application/pdf, application/octet-stream, application/vnd.openxmlformats-officedocument.spreadsheetml.sheet, application/vnd.ms-excel, text/csv o application/zip.

Body

Archivo binario (PDF, Excel, CSV o ZIP). El dry-run público acepta solo PDF.

Respuestas

  • 202 Accepted — devuelve { ok, jobId, estimate, ... }
  • 400/401/422 — errores de validación/auth

cURL rápido

curl -X POST "$BASE/forusbot/vault-file-upload" \
  -H "x-auth-token: <TOKEN>" \
  -H "x-filename: document.pdf" \
  -H 'x-meta: {"planId":580,"formData":{"section":"CONTRACTS & AGREEMENTS","caption":"Recordkeeper Agreement","status":"Audit Ready","effectiveDate":"2025-05-02"}}' \
  -H "Content-Type: application/pdf" \
  --data-binary @document.pdf

Scrape Plan Bot

Raspa datos de configuración del plan por planId. Extrae datos estructurados de 6 módulos (67 campos totales) más el historial de notas del plan. Soporta selección de campos y múltiples modos de retorno. Devuelve 202 Accepted con jobId; consulta /forusbot/jobs/:id para resultados.

Endpoint

POST /forusbot/scrape-plan (auth)

Body JSON

Campo Tipo Req Descripción
planId string sí ID del plan objetivo (ej., "627").
modules array no Lista de módulos a extraer. Puede ser strings (ej., "basic_info") o objetos con selección de campos (ej., {"key":"plan_design","fields":[...]}). Por defecto ["basic_info"] si se omite.
return enum no data|html|text|both (por defecto data).
strict boolean no Falla todo el job si algún módulo/campo falla la validación (por defecto false).
includeScreens boolean no Incluir capturas de evidencia.
timeoutMs number no Timeout del job en milisegundos (por defecto 30000).

Módulos Disponibles

  • basic_info — 16 campos (ID del plan, nombre de empresa, EIN, estado, fechas, gerentes)
  • plan_design — 26 campos (record keeper, elegibilidad, contribuciones, inscripción, crypto)
  • onboarding — 6 campos (primera fecha de diferimiento, fechas de blackout, fecha de activación)
  • communications — 6 campos (texto DAVE, logo, participantes en español, e-statement, sorteo)
  • extra_settings — 10 campos (modo de carga RK, año del plan, elegibilidad ER match)
  • feature_flags — 3 campos (Payroll X-Ray, problema de nómina, carga simple)

cURL rápido

curl -X POST "$BASE/forusbot/scrape-plan" \
  -H "x-auth-token: <TOKEN>" -H "Content-Type: application/json" \
  -d '{"planId":"627","modules":["basic_info","plan_design"]}'

Search Participants Bot

Busca participantes con criterios flexibles. Soporta controles de paginación y límites de resultado; devuelve filas normalizadas y un resumen de paginación.

Endpoint

POST /forusbot/search-participants (auth)

Body JSON

Ruta Tipo Req Descripción
criteria.companyName string no Filtra por empresa.
criteria.fullName string no Filtra por nombre completo.
criteria.email string no Email.
criteria.ssn string no SSN (últimos 4 soportados).
criteria.phone string no Teléfono (dígitos).
criteria.participantId string no ID exacto.
options.fetchAllPages boolean no Si es true, recorre páginas hasta pageLimit o maxRows.
options.pageLimit number no Límite duro de páginas (por defecto 1).
options.maxRows number no Máximo de filas a devolver (por defecto 25).
options.timeoutMs number no Timeout general.

Nota: Si maxRows es pequeño, la ejecución puede detenerse tras la primera página aun con fetchAllPages=true.

cURL rápido

curl -X POST "$BASE/forusbot/search-participants" \
  -H "x-auth-token: <TOKEN>" -H "Content-Type: application/json" \
  -d '{"criteria":{"fullName":"miguel"},"options":{"fetchAllPages":true,"pageLimit":5,"maxRows":250}}'

Update Participant Bot

Actualiza campos de datos censales del participante incluyendo nombre, dirección, fechas y estado de elegibilidad. Se requiere una nota documentando el motivo de la actualización. Devuelve 202 Accepted con jobId.

Endpoint

POST /forusbot/update-participant (auth)

Body JSON

Campo Tipo Req Descripción
participantId string sí ID del participante objetivo
note string sí Motivo de la actualización (requerido para auditoría)
updates object sí Etiquetas exactas de Census como First Name, Hire Date y Address 1.
options object no Opciones adicionales (evidenceOnSuccess, etc.)

Campos Disponibles para Actualización

First Name, Last Name, Preferred First Name, Preferred Last Name, Eligibility Status (A/D/I/X/U), Birth Date, Hire Date, Rehire Date, Termination Date, Projected Plan Entry Date, Address 1, Address 2, City, State, Zip Code, Primary Email, Home Email y Phone. Las etiquetas distinguen mayúsculas; no se aceptan nombres internos camelCase.

cURL rápido

curl -X POST "$BASE/forusbot/update-participant" \
  -H "x-auth-token: <TOKEN>" -H "Content-Type: application/json" \
  -d '{"participantId":"12345","note":"Corrigiendo fecha de contratación","updates":{"Hire Date":"2024-01-15","State":"CA"}}'

Jobs API — shape público

  • Estados: queued, running, succeeded, failed, canceled.
  • Campos: sólo state para queued/running/canceled; state + error en failed; state + data + warnings + errors en succeeded. No se exponen jobId, botId, meta, stages, createdBy ni métricas de ejecución.
  • data depende del bot (p. ej. scrape-participant devuelve {participantId, census?, savings_rate?, ...}). Para forensics detallado con stages, eco de meta, timestamps y métricas, usa GET /forusbot/admin/jobs-db/:id (solo admin).

Esquemas

x-meta (compartido)

{
  "planId": number,
  "formData": {
    "section": string,
    "caption": string,
    "captionOtherText"?: string,
    "status": string,
    "effectiveDate": "YYYY-MM-DD"
  },
  "options"?: {
    "returnEvidenceBase64"?: boolean,
    "saveEvidenceToTmp"?: boolean,
    "confirmDelayMs"?: number,
    "fastExit"?: boolean,
    "snifferWindowMs"?: number,
    "suppressSameUrlWarning"?: boolean,
    "evidenceOnSuccess"?: boolean,
    "skipPrevalidation"?: boolean
  }
}

202 Accepted (submit)

{
  "ok": true,
  "jobId": "uuid",
  "acceptedAt": "....",
  "queuePosition": 3,
  "estimate": { "method":"lanes+movingAvg", ... },
  "capacitySnapshot": { ... }
}

Job (GET /jobs/:id) — shape público

// queued / running / canceled
{ "state": "queued" }

// failed
{
  "state": "failed",
  "error": { "code": "ERROR", "message": "Login failed" }
}

// succeeded — el shape de `data` depende del bot
{
  "state": "succeeded",
  "data": { "participantId": "158948", "census": { ... } },
  "warnings": [],
  "errors": []
}

// Para verbose: GET /forusbot/admin/jobs-db/:id (solo token admin)

Ejemplos cURL

Crear job (202)

META='{"planId":580,"formData":{"section":"CONTRACTS & AGREEMENTS","caption":"Recordkeeper Agreement","status":"Audit Ready","effectiveDate":"2025-05-02"}}'

curl -sS -X POST https://TU_URL/forusbot/vault-file-upload \
  -H 'x-auth-token: TU_TOKEN' \
  -H 'x-filename: presentation.pdf' \
  -H 'Content-Type: application/octet-stream' \
  -H "x-meta: $META" \
  --data-binary @presentation.pdf

Consultar un job

curl -sS -H 'x-auth-token: TU_TOKEN' \
  https://TU_URL/forusbot/jobs/JOB_ID

Listar jobs

curl -sS -H 'x-auth-token: TU_TOKEN' \
  'https://TU_URL/forusbot/jobs?state=queued&limit=20'

Cancelar un job en cola

curl -sS -X DELETE -H 'x-auth-token: TU_TOKEN' \
  https://TU_URL/forusbot/jobs/JOB_ID

Cambiar visibilidad de status

curl -sS -X PATCH https://TU_URL/forusbot/settings \
  -H 'x-auth-token: TU_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"flags":{"statusPublic":false}}'

Variables de entorno

# Requeridas
PORT=10000
TOKENS_FILE=tokens.json     # override opcional de ruta

# Credenciales del portal
SITE_USER=...
SITE_PASS=...
TOTP_SECRET=...        # Base32, sin espacios
TOTP_STEP_SECONDS=30

# Concurrencia & ETA
MAX_CONCURRENCY=3
ESTIMATE_AVG_SECONDS=120
ESTIMATE_AVG_WINDOW=10

# Evidencias
EVIDENCE_DIR=/tmp/evidence

# Playwright
HEADLESS=1            # preferido: 1=headless, 0=con ventana
HEADFUL=0             # fallback legacy si HEADLESS no está definido
SLOWMO=0              # ms por acción
CLOSE_KILL_MS=1500

HEADLESS tiene prioridad. Si ninguna variable está definida, Chromium se ejecuta headless.

Evidencias

Las capturas se guardan en /tmp/evidence. En dev se exponen vía GET /evidence/*. En producción puedes deshabilitar el acceso público.

Errores & Warnings

  • 400 Bad Request — x-meta inválido o falta el archivo.
  • 401 Unauthorized — token inválido/ausente.
  • 409 Conflict — intento de cancelar un job que ya está corriendo.
  • 422 Unprocessable Entity — regla de negocio rechazada.
  • 500 — error inesperado.
