Overview

ForUsBots exposes nine Playwright automation bots for vault uploads, participant and plan scraping, participant search, MFA reset, participant and plan updates, email triggers, and portal user management. Protected operations use token-specific portal accounts, TOTP when required, and an asynchronous 202 + jobId workflow.

Docs audited: 2026-08-03 · API v2.6.0

Base URLs

  • DEV http://localhost:10000
  • Render https://forusbots.onrender.com

All API routes are namespaced under /forusbot.

Authentication

Protected routes accept x-auth-token or Authorization: Bearer …. Tokens are defined in the gitignored tokens.json registry (or TOKENS_FILE). A deployment may materialize that file from the TOKENS_JSON secret. Missing or unknown tokens return 401. 

x-auth-token: YOUR_TOKEN

Roles are admin, user, pa_lead, rm_lead, ops_lead, and imp_lead. Effective scope merges role defaults with token-level deniedFeatures, deniedEndpoints, and allowedEndpoints; an exact allow overrides denies. Inspect the resolved identity, account alias, and scope with GET /forusbot/whoami.

Locks, settings, metrics, version, and served OpenAPI are admin-only. Update-plan and users-management also use email allowlists; being an admin does not bypass those restrictions. Status depends on runtime flags.

Bots

High-level overview of the automation bots. For full specs and response examples, follow each link to the API Reference.

Vault File Upload Bot

Automates secure uploads to the ForUsAll Employer Portal. Accepts a binary body and metadata in headers; returns 202 Accepted with a jobId for polling.

Endpoint

POST /forusbot/vault-file-upload (auth)

Headers

Name Type Req Description
x-auth-token string yes Shared API token.
x-filename string yes Original filename. Supports .pdf, .xlsx, .xls, .csv, and .zip.
x-meta JSON string yes Includes planId and formData (section, caption, status, effectiveDate).
Content-Type enum yes application/pdf, application/octet-stream, application/vnd.openxmlformats-officedocument.spreadsheetml.sheet, application/vnd.ms-excel, text/csv, or application/zip.

Body

Binary file (PDF, Excel, CSV, or ZIP). The public dry-run remains PDF-only.

Responses

  • 202 Accepted — returns { ok, jobId, estimate, ... }
  • 400/401/422 — validation/auth errors

Quick cURL

curl -X POST "$BASE/forusbot/vault-file-upload" \
  -H "x-auth-token: <TOKEN>" \
  -H "x-filename: document.pdf" \
  -H 'x-meta: {"planId":580,"formData":{"section":"CONTRACTS & AGREEMENTS","caption":"Recordkeeper Agreement","status":"Audit Ready","effectiveDate":"2025-05-02"}}' \
  -H "Content-Type: application/pdf" \
  --data-binary @document.pdf

Scrape Participant Bot

Scrapes participant data by participantId. Supports selecting modules and return modes. Returns 202 Accepted with a jobId; poll /forusbot/jobs/:id for results.

Endpoint

POST /forusbot/scrape-participant (auth)

JSON Body

Field Type Req Description
participantId string yes Target participant.
return enum no data|html|text|both (default data).
strict boolean no Stricter parsing/guards.
includeScreens boolean no Attach screenshots when available.
timeoutMs number no Global timeout per run.
modules array no Module keys or descriptors, e.g. ["census",{"key":"payroll","fields":["Latest Payroll","years:2026"]}].

  -d '{"participantId":"12345","return":"data","strict":true,"modules":["census",{"key":"payroll","fields":["Latest Payroll","years:2026"]}]}'

Scrape Plan Bot

Scrapes plan configuration data by planId. Extracts structured data from 6 modules (67 total fields) plus plan notes history. Supports field selection and multiple return modes. Returns 202 Accepted with a jobId; poll /forusbot/jobs/:id for results.

Endpoint

POST /forusbot/scrape-plan (auth)

JSON Body

Field Type Req Description
planId string yes Target plan ID (e.g., "627").
modules array no List of modules to extract. Can be strings (e.g., "basic_info") or objects with field selection (e.g., {"key":"plan_design","fields":[...]}). Defaults to ["basic_info"] if omitted.
return enum no data|html|text|both (default data).
strict boolean no Fail entire job if any module/field validation fails (default false).
includeScreens boolean no Include evidence screenshots.
timeoutMs number no Job timeout in milliseconds (default 30000).

Available Modules

  • basic_info — 16 fields (plan ID, company name, EIN, status, dates, managers)
  • plan_design — 26 fields (record keeper, eligibility, contributions, enrollment, crypto)
  • onboarding — 6 fields (first deferral date, blackout dates, website live date)
  • communications — 6 fields (DAVE text, logo, Spanish participants, e-statement, raffle)
  • extra_settings — 10 fields (RK upload mode, plan year, ER match eligibility)
  • feature_flags — 3 fields (payroll X-Ray, payroll issue, simple upload)

Quick cURL

curl -X POST "$BASE/forusbot/scrape-plan" \
  -H "x-auth-token: <TOKEN>" -H "Content-Type: application/json" \
  -d '{"planId":"627","modules":["basic_info","plan_design"]}'

Search Participants Bot

Searches participants with flexible criteria. Supports pagination controls and result limits; returns normalized rows and a pagination summary.

Endpoint

POST /forusbot/search-participants (auth)

JSON Body

Path Type Req Description
criteria.companyName string no Filter by company name.
criteria.fullName string no Filter by full name.
criteria.email string no Email filter.
criteria.ssn string no SSN (last 4 supported).
criteria.phone string no Phone digits.
criteria.participantId string no Exact id.
options.fetchAllPages boolean no If true, iterates pages up to pageLimit and until maxRows is reached.
options.pageLimit number no Hard cap on paged traversal (default 1).
options.maxRows number no Maximum rows to return (default 25).
options.timeoutMs number no Overall timeout.

Note: If maxRows is small, the run may stop after the first page even with fetchAllPages=true.

Quick cURL

curl -X POST "$BASE/forusbot/search-participants" \
  -H "x-auth-token: <TOKEN>" -H "Content-Type: application/json" \
  -d '{"criteria":{"fullName":"miguel"},"options":{"fetchAllPages":true,"pageLimit":5,"maxRows":250}}'

Update Participant Bot

Updates participant census data fields including name, address, dates, and eligibility status. A note documenting the reason for the update is required. Returns 202 Accepted with jobId.

Endpoint

POST /forusbot/update-participant (auth)

JSON Body

Field Type Req Description
participantId string yes Target participant ID
note string yes Reason for the update (required for audit trail)
updates object yes Exact Census UI labels such as First Name, Hire Date, and Address 1.
options object no Additional options (evidenceOnSuccess, etc.)

Available Update Fields

First Name, Last Name, Preferred First Name, Preferred Last Name, Eligibility Status (A/D/I/X/U), Birth Date, Hire Date, Rehire Date, Termination Date, Projected Plan Entry Date, Address 1, Address 2, City, State, Zip Code, Primary Email, Home Email, and Phone. Labels are case-sensitive; internal camelCase names are not accepted.

Quick cURL

curl -X POST "$BASE/forusbot/update-participant" \
  -H "x-auth-token: <TOKEN>" -H "Content-Type: application/json" \
  -d '{"participantId":"12345","note":"Correcting hire date","updates":{"Hire Date":"2024-01-15","State":"CA"}}'

Jobs API — public shape

  • States: queued, running, succeeded, failed, canceled.
  • Fields: only state for queued/running/canceled; state + error on failed; state + data + warnings + errors on succeeded. No jobId, botId, meta, stages, createdBy, or runtime metrics are exposed.
  • data is bot-specific (e.g. scrape-participant returns {participantId, census?, savings_rate?, ...}). For verbose forensics with stages, meta echo, timestamps, and metrics, use GET /forusbot/admin/jobs-db/:id (admin only).

Request & Response Schemas

x-meta (shared)

{
  "planId": number,
  "formData": {
    "section": string,
    "caption": string,
    "captionOtherText"?: string,
    "status": string,
    "effectiveDate": "YYYY-MM-DD"
  },
  "options"?: {
    "returnEvidenceBase64"?: boolean,
    "saveEvidenceToTmp"?: boolean,
    "confirmDelayMs"?: number,
    "fastExit"?: boolean,
    "snifferWindowMs"?: number,
    "suppressSameUrlWarning"?: boolean,
    "evidenceOnSuccess"?: boolean,
    "skipPrevalidation"?: boolean
  }
}

{
  "ok": true,
  "jobId": "uuid",
  "acceptedAt": "2025-08-20T00:00:00Z",
  "queuePosition": 3,
  "estimate": {
    "method": "lanes+movingAvg",
    "avgDurationSeconds": 120,
    "startAt": "...",
    "finishAt": "..."
  },
  "capacitySnapshot": { ... }
}

Environment & Defaults

# Required
PORT=10000
TOKENS_FILE=tokens.json     # optional path override

# Portal credentials
SITE_USER=...
SITE_PASS=...
TOTP_SECRET=...        # Base32, no spaces
TOTP_STEP_SECONDS=30

# Concurrency & ETA
MAX_CONCURRENCY=3
ESTIMATE_AVG_SECONDS=120
ESTIMATE_AVG_WINDOW=10

# Evidence
EVIDENCE_DIR=/tmp/evidence

# Playwright
HEADLESS=1            # preferred: 1=headless, 0=headed
HEADFUL=0             # legacy fallback only when HEADLESS is unset
SLOWMO=0              # ms per action
CLOSE_KILL_MS=1500

HEADLESS takes precedence. If neither variable is set, Chromium runs headless.

Evidence Files

Evidence screenshots go to /tmp/evidence. In dev they are served via GET /evidence/*. Disable public access in production if not needed.

Errors & Warnings

  • 400 Bad Request — invalid x-meta, missing file.
  • 401 Unauthorized — bad/missing token.
  • 409 Conflict — cancel attempted on a running job.
  • 422 Unprocessable Entity — business rule rejection.
  • 500 — unexpected error.
